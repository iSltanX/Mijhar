الهدف

اتصال Local Debug (التشخيص المتقدم / Remote File Access) ينقطع لما التطبيق يطلع للخلفية أو حتى عند .inactive (مركز التحكم)، وما يرجع يتصل تلقائياً.

السبب

ETOS LLM Studio/ETOS LLM Studio iOS App/Views/LocalDebugView.swift (حوالي السطر 253):

.onChange(of: scenePhase) { _, newPhase in
    if newPhase != .active && server.isRunning { disconnectServer() }
}

disconnectServer() → server.disconnect() → stopAutoReconnect() (LocalDebugServerConnection.swift:160) فيمسح هدف إعادة الاتصال. نفس الشي في Watch LocalDebugView سطر 72.

المطلوب

  1. في LocalDebugView.swift (iOS و Watch): تجاهل .inactive. عند .background لا تفصل؛ ابدأ ApplicationBackgroundTaskLease("local-debug") وعند انتهائه استدعِ server.suspendForBackground(). عند .active أنهِ الـlease واستدعِ server.resumeIfNeeded(). زر Disconnect فقط يستدعي stopAutoReconnect().
  2. في LocalDebugServerConnection.swift: أضف suspendForBackground() (يلغي WebSocket/مؤقت HTTP/الجلسة مع إبقاء reconnectTarget وautoReconnectEnabled) وresumeIfNeeded() (إذا autoReconnectEnabled && !isRunning صفّر reconnectAttempt واتصل فوراً عبر مسار إعادة الاتصال الموجود).
  3. (iOS فقط) خيار جديد في AppConfig افتراضياً مغلق: "ابقَ متصلاً في الخلفية" — LocalDebugKeepAlive.swift يشغّل AVAudioSession بفئة .playback مع .mixWithOthers ويكرر buffer صامت بـ AVAudioEngine طول ما الاتصال شغال والخيار مفعّل، ويوقف عند الفصل. وضع audio موجود أصلاً في iOSInfo.plist. أضف مفتاح الإعداد في صفحة التشخيص المتقدم مع نصوص عربي/إنجليزي/صيني.
  4. (اختياري) إشعار محلي إذا فشل الاتصال بعد نفاد المحاولات.

القواعد

  • غيّر أقل قدر ممكن، والتزم بأسلوب الكود الموجود.
  • افتح PR على فرع جديد، واشرح التغييرات بالعربي باختصار.
  • لا تطبع أي مفاتيح أو أسرار.

    4. معالجة المقاطعات وفقد خدمات الصوت واستعادتها وفشل التشغيل، وتجاهل النتائج المتأخرة الخاصة بمشغّل سابق.
    5. التحقق من الانتقال بين الصوت الصامت والقراءة، والانتظار، والتوقف المؤقت، وانتهاء القراءة، والمقاطعات، والفصل اليدوي، مع تشغيل خيار الصوت الصامت وتعطيله.

    بناءً على طلب المستخدم: هذه طريقة تنزيل المهارات واستيرادها إلى ETOS على الآيفون. هذا تسليم تعليمات؛ ليس أمرًا بتثبيت مجموعة مهارات أو تشغيل سكربتاتها الآن.

    1. افحص الأدوات المتاحة فعلًا في جلستك. البحث/التصفح يجلب المصدر، وأدوات الملفات تحفظه. أداة use_skill تتعامل مع المهارات المثبتة والمفعلة؛ إجراءاتها للقراءة والموارد وتشغيل السكربتات، وليست محرك بحث أو أداة تنزيل/استيراد. لا تخترع أداة غير معروضة.

    2. ابحث عن المهارة المناسبة، ثم افتح مستودعها الأصلي واقرأ SKILL.md والمتطلبات. تحقّق من name وdescription ومن الموارد المشار إليها. رابط صفحة توثيق أو صفحة نتائج بحث ليس حزمة مهارة. احتفظ برابط المصدر والنسخة/commit التي راجعتها إن توفر.

    3. المسار المدمج في واجهة iOS:
      الإعدادات ← مهارات الوكيل ← استيراد من جيثب ← عنوان URL للمستودع ← استيراد.
      يدعم رابط المجلد /tree/<branch>/<path>. عند وجود عدة مهارات في المستودع، استخدم رابط مجلد المهارة المحدد. رابط SKILL.md المباشر في خانة الروابط يجلب الملف فقط، وليس موارده. توجد أيضًا خيارات لصق SKILL.md، واستيراد حزمة محلية، واستيراد رابط مباشر لـ SKILL.md أو ZIP. هذه خطوات واجهة للمستخدم ما لم توجد لديك أداة فعلية للتحكم بها؛ لا تدّعِ الضغط على أزرار لم تضغطها.

    4. عند وجود تفويض بالتنزيل وأدوات ملفات مناسبة، يمكن تجهيز المهارة يدويًا:

    • افحص مكان مكتبة Skills الحقيقية أولًا. أدوات sandbox قد تشير إلى مساحة عمل مختارة بدل Documents؛ وكتابة الملفات في Linux أو مجلد عمل عشوائي لا تعني استيرادها إلى مكتبة التطبيق.
    • إذا كانت الأدوات المعروضة تشمل app_create_sandbox_directory وapp_write_sandbox_file وكان نطاقها الصحيح مؤكدًا، احفظ الحزمة تحت Skills/<skill-name>/، وملفها الرئيسي Skills/<skill-name>/SKILL.md.
    • انقل الموارد التي تحتاجها المهارة مع الحفاظ على المسارات النسبية والملفات الثنائية كما هي. إذا لم تتوفر وسيلة تحفظ الحزمة كاملة، سلّم رابط الاستيراد المدمج بدل حفظ نسخة ناقصة.
    • لا تستبدل مهارة موجودة بصمت، ولا تنفذ أوامر تثبيت مأخوذة من README لمجرد تنزيل التعليمات.

    1. تحقّق بعد الحفظ/الاستيراد من ظهور المهارة ومحتواها، ومن تفعيلها ومن المفتاح العام «السماح للذكاء الاصطناعي باستخدام المهارات». الملف المحفوظ وحده ليس دليلًا على أن النموذج يستطيع استخدامه. جرّب قراءة تعليماتها عبر الأداة الفعلية، ثم اذكر: المصدر، ما تم حفظه، حالة التفعيل، وما تم اختباره. الاستيراد من واجهة التطبيق يفعّل المهارة المستوردة وفق المصدر الحالي، لكن الكتابة المباشرة بأدوات الملفات لا تفعّل اسمًا جديدًا: افتح صفحة مهارات الوكيل لإعادة قراءة الملفات ثم فعّل المهارة. لا تفترض اكتشافًا فوريًا. انتبه أن استيراد اسم موجود يمكن أن يستبدل مجلده كاملًا، وليس مجرد دمج الملفات.

    2. تنزيل المهارة منفصل عن تنفيذها. تشغيل سكربتاتها يخضع لوضع Agent وLinux المحلي وسياسة الموافقة والأدوات المتاحة. allowed-tools لا يمنح صلاحيات جديدة. بعض مهارات SwiftUI تحتاج Xcode أو Instruments على Mac، ولا تتوفر تلك البرامج لمجرد وجود Linux في الآيفون.

    روابط مجلدات تحققت منها للترشيح عند الحاجة:

    • SwiftUI Expert: https://github.com/AvdLee/SwiftUI-Agent-Skill/tree/main/skills/swiftui-expert-skill
      استورد المجلد الحقيقي مع المراجع. بعض أدوات تحليل الأداء تحتاج Python 3 وxctrace على Mac.
    • Systematic Debugging: https://github.com/obra/superpowers/tree/main/skills/systematic-debugging
      تعليمات تشخيص الأخطاء مفيدة، لكن السكربت المساعد في جذر المهارة لا يطابق مباشرة شرط scripts/ في use_skill.execute_script. المهارات الأخرى التي تحيل إليها ليست مثبتة تلقائيًا.

    مرجع ETOS:
    https://github.com/Eric-Terminal/ETOS-LLM-Studio/blob/main/docs/site/en/modules/skills-and-shortcuts.md
