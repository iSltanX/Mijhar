## العنوان والوصف

**Local Debug: إعادة الاتصال التلقائي + البقاء متصلاً في الخلفية**

> @codex
>
> الهدف
>
> اتصال Local Debug (التشخيص المتقدم / Remote File Access) ينقطع لما التطبيق يطلع للخلفية أو حتى عند .inactive (مركز التحكم)، وما يرجع يتصل تلقائياً.
>
> السبب
>
> ETOS LLM Studio/ETOS LLM Studio iOS App/Views/LocalDebugView.swift (حوالي السطر 253):
>
> .onChange(of: scenePhase) { _, newPhase in
>     if newPhase != .active && server.isRunning { disconnectServer() }
> }
>
> disconnectServer() → server.disconnect() → stopAutoReconnect() (LocalDebugServerConnection.swift:160) فيمسح هدف إعادة الاتصال. نفس الشي في Watch LocalDebugView سطر 72.
>
> المطلوب
>
> - في LocalDebugView.swift (iOS و Watch): تجاهل .inactive. عند .background لا تفصل؛ ابدأ ApplicationBackgroundTaskLease("local-debug") وعند انتهائه استدعِ server.suspendForBackground(). عند .active أنهِ الـlease واستدعِ server.resumeIfNeeded(). زر Disconnect فقط يستدعي stopAutoReconnect().
> - في LocalDebugServerConnection.swift: أضف suspendForBackground() (يلغي WebSocket/مؤقت HTTP/الجلسة مع إبقاء reconnectTarget وautoReconnectEnabled) وresumeIfNeeded() (إذا autoReconnectEnabled && !isRunning صفّر reconnectAttempt واتصل فوراً عبر مسار إعادة الاتصال الموجود).
> - (iOS فقط) خيار جديد في AppConfig افتراضياً مغلق: "ابقَ متصلاً في الخلفية" — LocalDebugKeepAlive.swift يشغّل AVAudioSession بفئة .playback مع .mixWithOthers ويكرر buffer صامت بـ AVAudioEngine طول ما الاتصال شغال والخيار مفعّل، ويوقف عند الفصل. وضع audio موجود أصلاً في iOSInfo.plist. أضف مفتاح الإعداد في صفحة التشخيص المتقدم مع نصوص عربي/إنجليزي/صيني.
> - (اختياري) إشعار محلي إذا فشل الاتصال بعد نفاد المحاولات.
>
> القواعد
>
> - غيّر أقل قدر ممكن، والتزم بأسلوب الكود الموجود.
> - افتح PR على فرع جديد، واشرح التغييرات بالعربي باختصار.
> - لا تطبع أي مفاتيح أو أسرار.
