# MJ11 — تفسير الموانع ومحلل السجل وطبقة API العامة وتجربة جدوى الطبقة المساعدة

> «ماذا ولماذا» في الخطة: [`T-5.2`](../../phases/phase-05-module-d.md#T-5.2) · [`T-5.3`](../../phases/phase-05-module-d.md#T-5.3) · [`T-0.5`](../../phases/phase-00-feasibility.md#T-0.5)، والقسم 6 من [`EXECUTION_PLAN.md`](../../EXECUTION_PLAN.md). و«متى وكيف» في [`Docs/MJ/README.md`](../README.md).

## الهدف

الطبقة الثانية للوحدة (د): تفسير موانع الدمج بالأدلة وبيان المصدر والتقادم وطبقة REST API العامة عبر الصلاحية الاختيارية، ومحلل وشرح سجل الفحص بثلاث طبقات. ومعها تجربة الجدوى الخامسة (`T-0.5`): الحافظة، ومسار طلب مزوّد التحليل وتقدير تكلفته، وأقل صلاحيات رمز GitHub وإشاراته وحدود طلباته — وثيقة قياس تبني عليها كل مراحل الطبقة المساعدة (`MJ18` إلى `MJ22`).

## لماذا الآن

تعتمد على بطاقة حالة PR المدمجة في D وعلى `T-0.3`؛ ملفاتها في `modules/d` و`core/api` منفصلة. و`T-0.5` وُضعت هنا بتوسيع 2026-10-23 لأنها تجربة قياس لا تعتمد على شيء، ويجب أن تُدمج قبل الموجة F حيث تبني عليها `T-5.5`؛ وملفاتها في `evidence/` و`fixtures/` لا تتقاطع مع شيء.

## النطاق

**الملفات التي تملكها المرحلة**

- `src/modules/d/blockers/` و`src/modules/d/log-parser/` و`src/core/api/` (طبقة الطلبات العامة والتخزين المؤقت وترويسات `x-ratelimit-*`)
- `tests/modules/d/` و`tests/core/api/` و`fixtures/logs/`
- `evidence/T-0.5/` و`scripts/spikes/` و`fixtures/spikes/` (تجربة الجدوى الخامسة)

**الملفات المشتركة مع مراحل الموجة** (تُضم بترتيب الدمج لا باختيار نسخة)

- `src/core/index.ts`: تصدير طبقة API.

**خارج النطاق**

- رمز الوصول (`MJ15`): هنا طلبات عامة بلا مصادقة فقط؛ و`T-0.5` تقيس صلاحيات الرمز وإشاراته ولا تبني مسار إدخال ولا تخزين.
- بناء أي طبقة مزوّد أو زر نسخ (`MJ18` إلى `MJ22`): `T-0.5` تقيس ولا تبني.

## المهام

1. `T-5.2` — تفسير موانع الدمج بالأدلة وبيان المصدر والتقادم وطبقة API العامة (`F-D3`, `F-D4`) ([التفاصيل ومعايير القبول](../../phases/phase-05-module-d.md#T-5.2)).
2. `T-5.3` — محلل وشرح سجل الفحص بثلاث طبقات (`F-D5`) ([التفاصيل ومعايير القبول](../../phases/phase-05-module-d.md#T-5.3)).
3. `T-0.5` — تجربة جدوى الطبقة المساعدة: الحافظة، والوصول المباشر إلى مزوّد التحليل وتقدير تكلفته، وصلاحيات رمز GitHub الدنيا وإشاراته وحدود طلباته ([التفاصيل ومعايير القبول](../../phases/phase-00-feasibility.md#T-0.5)) — **مستقلة** عن المهمتين السابقتين.

## الاعتماديات

- **مراحل يلزم دمجها قبل البدء:** `MJ4`، `MJ8`.
- **تعمل بالتوازي مع:** `MJ10`، `MJ12`.
- **قرارات تمسّها:** لا شيء يوقفها. و`T-0.5` **تغذّي** `DEC-09` و`DEC-10` المحسومين (فتثبت أو تنقض أساسهما التقني) وتُقاس بها `HYP-07` و`HYP-09` و`HYP-17` و`HYP-18` و`HYP-19`؛ و`AC-S5.3` لا ينطبق إلا في فرع دعم الرمز من `DEC-04` وقد حُسم إلى د-5 فينطبق.

## معايير القبول

- `AC-D3`: كل سبب لمنع الدمج معروض مقرون بدليل مرصود (نص في صندوق الدمج أو حقل في API)؛ لا يُعرض سبب بلا دليل؛ التنبيه المنهجي الدائم بأن نجاح الفحوص لا يعني جاهزية المشروع ظاهر؛ ولا تظهر عبارة تجزم بأن الطلب «جاهز للدمج».
- `AC-D4`: تعرض الشارة المصدر (DOM أو DOM + API) ووقت آخر قراءة؛ وتظهر التنبيهات في ثلاث حالات: قائمة فحوص مطوية جزئيًا، تجاوز عتبة التقادم القابلة للضبط، ورود تحديث حي؛ وبعد التحديث يتجدد الوقت.
- `AC-S5.1`: سلوك الكتابة إلى الحافظة موثق لكل متصفح مُختبَر من سياق محقون في صفحة GitHub وبنقر مستخدم: ما نجح، وما فشل وبأي خطأ، وهل يلزم صلاحية أو تركيز نافذة، وما البديل اليدوي العامل عند الفشل؛ وما تعذّر قياسه يُسجَّل «لم يُجرَ» بسببه.
- `AC-S5.2`: مسار طلب مزوّد التحليل من سياق الإضافة موثق بالتجربة: السياق الذي نجح منه (الخلفية أو صفحة الإضافة أو سكربت المحتوى) وما فشل، والترويسات التي لزمت، وسلوك `CORS`، وهل يعمل البث؛ وإن تعذّر القياس لعدم توفر مفتاح تجريبي يُسجَّل «لم يُجرَ» بسببه ولا يُفترض النجاح ولا يُبنى عليه.
- `AC-S5.3`: أقل صلاحيات رمز GitHub دقيق الحبيبات اللازمة لكل نقطة نهاية تستخدمها الخطة (قراءةً فقط) مثبتة بتجربة فعلية: ما يُقبل وما يُرفض بأقل صلاحية؛ وجدول إشارات انتهاء الرمز ونقص الصلاحية وتجاوز الحد كما تظهر في رمز الاستجابة وجسمها وترويساتها. (هذا المعيار يُعيد قياس ما عُلِّم «لا ينطبق» في `AC-S3.3` حين كان `DEC-04` محسومًا بـد-4.)
- `AC-S5.4`: حدود الطلبات الموثَّقة مقابل غير الموثَّقة مقروءة من ترويسات `x-ratelimit-*` ومسجَّلة بقيمها ووقتها، وسلوك الوصول إلى السجل الخام بمصادقة موثق (نجح أم لا ولماذا)؛ ودقة تقدير التكلفة قبل الإرسال مسجَّلة بفرقها عن الاستهلاك المُعلن في الاستجابة، أو «غير قابل للحساب» بسببه، مع مصدر الأسعار وتاريخ قراءته.
- `AC-D5`: على السجل المرجعي: الطبقة الأولى تعرض الرسالة الحرفية وموضعها (الخطوة وكود الخروج والأسطر المحيطة)؛ الطبقة الثانية لا تُملأ إلا عند تطابق نمط حتمي من قائمة الأنماط المعرّفة وإلا ظهرت عبارة «لا يوجد سبب جذري مثبت من نص السجل وحده»؛ الطبقة الثالثة موسومة «احتمال يحتاج تحققًا»؛ لا تختلط الطبقات؛ والسجل المقتطع أو غير المتاح يُعلَن.

## الفحوص

- اختبارات الخطة لمهام المرحلة: `TEST-PR-03`، `TEST-PR-04`، `TEST-LOG-01`، `TEST-SPIKE-05`.
- `npx vitest run tests/modules/d tests/core/api` أخضر (`TEST-PR-03` و`TEST-PR-04` و`TEST-LOG-01`).
- تدقيق شبكة: لا طلب إلى `api.github.com` دون الصلاحية الاختيارية الممنوحة بنقر صريح؛ مسجَّل في `evidence/T-5.2/`.
- `TEST-SPIKE-05`: تُسجَّل نتائج `T-0.5` كما هي في `evidence/T-0.5/report.md` مع الخام، وما تعذّر يُسجَّل «لم يُجرَ» بسببه ولا يُعدّ نجاحًا؛ ولا تُجرى التجربة على مستودع خاص لغير المالك ولا يُنشر فيها محتوى.
- المتصفحات المتاحة Chrome وEdge وBrave وFirefox 158.0.1 (`EV-09`)؛ وأي بند يتعذر في متصفح يُسجَّل «لم يُجرَ» بسببه، ولا يُغلق به معيار.
- الفحوص بحسب الأثر: ما تمسّه المرحلة فقط، ولا يُعاد طقم كامل بعد كل تعديل؛ والفحوص التي تشترك في متصفح أو منفذ تُجرى متسلسلة.
